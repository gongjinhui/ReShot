# ReShot 1.9.1 标注交互修复

2026-11-07，构建 12，沿用 Bundle ID 和保存设置。最终构建摘要在 `evidence/reshot-1.9.1-build.json`。

用户反馈：标注时选区随鼠标移动，取消及返回箭头没有反应。本轮将“返回箭头”按工具栏撤销处理。

## 已复现原因

增加了真正调用视图命中、矩形按钮和画布鼠标 down/drag/up 的回归测试。修复前失败：“绘制矩形导致选区变化或未生成标注”。原 `ImageCanvas` 没有接管 mouseUp，默认响应链将松开事件向上传递；`PickerView.mouseUp` 无条件调用自身 mouseDragged，使用框选时留下的 anchor/creating 状态，因而修改了选区。裁切更新又重置标注文档的撤销历史。之前测试直接加入标注和调用接受/取消回调，漏掉了这条真实控件事件路径。

该复现证明了标注松开事件引发选区变化；没有单独观察到用户“取消无反应”的唯一原因，因此同时检查并加固工具栏鼠标处理，仍需实际鼠标复测。

## 修复

- 标注画布消费自己的 mouseUp，不再传给选区；画布可接受第一下点击。
- 选区只处理由自己 mouseDown 开始的拖动手势，处理完 mouseUp 清除手势状态，忽略子视图和无关的松开事件。
- 标注工具启用时固定选区，包括边缘落笔和选区外的事件。需切回“选择”后才能移动/缩放选区。
- 工具栏背景消费鼠标事件，按钮接受第一下点击；取消、撤销、重做、确认按钮仍使用各自目标动作。
- 覆盖窗口不允许背景拖动，画布和工具栏也不允许将鼠标按下用于拖窗。命中判断将传入的父视图坐标显式转为本地坐标。
- 新建未达到最小尺寸的选区时隐藏旧预览与工具栏，避免显示已失效的确认入口。
